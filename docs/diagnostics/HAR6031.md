# HAR6031: a query file's sent text isn't checked

**Warning.** Found by `haruspex check` with a baseline, for a query file. The check goes on.

## What it means

A query file is the application's own SQL, and the application already running sends the text it was built with. The check
infers only the file's text as it is now. With a baseline given as a source, the file is read as it is now on both sides, so
the fit holds for the running application only if its text hasn't changed since. With a baseline given as an IR file, the IR
holds the old text, and where that differs from the file's now, or the file is gone, what the old text returns from this
database isn't inferred, so the query file isn't judged.

## Why haruspex reports it

A check that passed without judging a query file would claim more than it showed.

## What to do

Give the baseline as the IR file the running application was built with, which holds the text it sends. Where the text
changed, make sure the old text still runs on the new database, or deploy the application before the database.

## Example

```text
sql/titles.sql:1:1: warning HAR6031: sql/titles.sql: the baseline is a source, so this query file is checked with its text as it is now; the application already running sends the text it was built with, which may differ. Give the baseline as the IR file it was built with to check that text.
```
