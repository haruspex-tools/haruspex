# HAR6010: a collation the package records otherwise

**Warning.** Found on the command line, or reading and writing files. The run goes on.

## What it means

The config file declares the database's default `collation`, but the source is a DACPAC that records a different one, or a
project file that gives one (its `DefaultCollation`, or a build's default when it sets none).

## Why haruspex reports it

The package's or project's collation is the database's own, the one a column without `COLLATE` takes when it deploys, so it is
the one haruspex uses, and the config file's does nothing. The two disagreeing usually means the setting was written for a folder of
scripts and the package is of another database, or the database's collation changed and the config file didn't.

## What to do

Remove `collation`, or correct it to the package's or project's if the same config file also reads the folder of scripts.

## Example

```text
haruspex.json: warning HAR6010: "collation" is Latin1_General_100_CI_AS, but atelier.dacpac records SQL_Latin1_General_CP1_CI_AS, the database's own, which is the one used.
```
