# HAR4115: a JSON Schema named in the SQL that can't be read

**Error.** Found applying the config file to the project. It stops the run: nothing is written.

## What it means

The extended property `haruspex.jsonSchema` is set in a way haruspex can't read for certain: its value isn't literal text (a
variable, or a number), it is empty, it is set twice on one column, it is updated or dropped rather than added, or it is on a
table, view, function, column or parameter the source doesn't define.

## Why haruspex reports it

The property declares a column's type. Passing it over would leave the column typed differently from what the team wrote,
without a word; reading it would guess at a value or at the order the scripts run in, which decides what stands after an
update or a drop.

## What to do

Name the schema once for the column, with `sp_addextendedproperty` and literal text, on a column the project defines. SQL Server
refuses a second add of one property (15233), and an annotation on something that doesn't exist (15135).

## Example

```text
db/p2.sql:1:1: error HAR4115: The JSON Schema of lib.book.extras is passed over: the table lib.book has no column extras.
```
