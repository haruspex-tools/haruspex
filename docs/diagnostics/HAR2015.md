# HAR2015: result sets that depend on the path taken

**Note.** Found inferring the results. The run goes ahead; a note never changes whether it succeeds.

## What it means

Result sets whose number or order depends on the path through the procedure in a way a list can't say: a result inside a
loop, or different encodings at one position. The value, or the result, is unknown in the output, with this reason, and
the generated schema accepts anything there.

## Why haruspex reports it

The output never claims more than SQL Server guarantees: what haruspex can't prove, it says it doesn't know, so the
output stays true. The note says where, so that an unknown is never silent.

## What to do

Return one result set per path, or the same ones on every path.

## Example

```text
db/p1.sql:1:34: note HAR2015: lib.p results: A result set is returned inside a loop, which may return it any number of times.
```
