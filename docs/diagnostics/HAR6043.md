# HAR6043: a baseline whose claims are another build's

**Warning.** Found by `haruspex check` or `haruspex generate`, reading a baseline given as an IR file. The run goes on.

## What it means

An IR file holds the claims of the build of haruspex that wrote it, which it names in `source.writtenBy` (IR 0.30). The
baseline names another build than the one running, or none: a file of IR 0.29 or earlier names no build, and a build made
without its commit (from a `git archive` copy or a source tarball) can't tell its own files from another's.

## Why haruspex reports it

A fix to one of haruspex's rules may withdraw a claim without changing the IR's version, so a file of a version this build
reads may still hold a claim this build knows to be false. The types written against the baseline would rest on it, with
nothing to say so ([decision 0117](../decisions/0117-an-ir-document-names-the-build-that-made-its-claims.md)).

## What to do

Give the baseline as the source it was inferred from (the release's `.dacpac`, its `.sqlproj` or its folder of scripts), which
this build infers again with its own rules. Where the baseline must be an IR file, because it holds the text of the query files
the running application sends ([HAR6031](HAR6031.md)), write it again with this build from the release's own checkout.

## Example

```text
haruspex: warning HAR6043: the baseline release.ir.json holds the claims of the haruspex that wrote it, 0.0.0-test (commit 111111111111), and this is 0.0.0-test (commit 000000000000). A fix made between the two may have withdrawn a claim the file holds, and the types would still rest on it. Give the baseline as the source it was inferred from (a .dacpac, a .sqlproj or a folder), which this haruspex infers again with its own rules.
```
