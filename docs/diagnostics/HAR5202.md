# HAR5202: a query file's parameter can't be declared

**Error.** Found emitting the database module's functions. It stops the run: nothing is written.

## What it means

A query file's function sends its text through `sp_executesql`, which needs each parameter declared with a type, and one
parameter can't be: its type isn't known (nothing in the file decides it, [HAR2024](HAR2024.md)), its type isn't one a
declaration can name, or its name is `@stmt` or `@params`, which are `sp_executesql`'s own.

## Why haruspex reports it

Without a type the call can't be made, and a type haruspex chose would be a guess: the function would check values against it,
and the server would convert them to it.

## What to do

Declare the parameter's type in the file, on a line of its own, as `DECLARE` would declare it (`-- @param @label nvarchar(40)`),
or rename a parameter called `@stmt` or `@params`. Without `"mssql"` in `"emit"`, the schemas are written and the parameter is
unknown in them.

## Example

```text
haruspex.json: error HAR5202: The function of sql/label.sql must declare @label to sp_executesql, and its type isn't known (undecided-parameter); declare it in the file, as -- @param @label <type>.
```
