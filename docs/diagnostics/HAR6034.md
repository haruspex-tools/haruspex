# HAR6034: a key that may have been renamed

**Warning.** Found by `haruspex generate` with a baseline, and by `haruspex check` with one (unless `--fit-only`). The run goes
on.

## What it means

In one result's object type, a key the baseline returns is gone from the source, and another has appeared. It may be a rename.
The combined type has both keys, each of which may be left out, since each database returns only one of them.

## Why haruspex reports it

Combined types are merged rather than given as alternatives: one object type with optional keys, easy to use but looser. A
rename becomes two optional keys, and the types allow an object with neither, which neither database returns. The application
has to read both names until the baseline moves on, and it is worth knowing that is what the change asks of it.

## What to do

If it is a rename, read the value under either name until the baseline moves on (`row.customer_name ?? row.customerName`), and
drop the old name then. If it isn't, nothing.

## Example

```text
db/p1.sql:1:1: warning HAR6034: lib.get_book results[0][]: note went and remark appeared; if it was renamed, read both until the baseline moves on. The combined type has both keys, each optional.
```
