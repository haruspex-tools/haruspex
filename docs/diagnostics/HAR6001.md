# HAR6001: the command line doesn't parse

**Error.** Found on the command line, or reading and writing files. It stops the run: nothing is written.

## What it means

The command line doesn't parse: an option haruspex doesn't know, or one without its value. An option the command doesn't have
is named as one, with the nearest it does have when one is close (`--color` for `--colour`), even where the command takes a
source: a token that starts with `-` is read as an option, not as a folder. To name a source that starts with `-`, write `--`
before it (`haruspex check -- -db`).

## Why haruspex reports it

A run that guessed what was meant could write somewhere unexpected.

## What to do

Correct the command; `haruspex --help` lists the options (from a clone, `dotnet run --project src/Haruspex.Cli -- --help`).

## Example

```text
haruspex: error HAR6001: --colour is not an option of haruspex generate; the nearest is --color.
```
