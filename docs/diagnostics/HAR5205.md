# HAR5205: a parameter the driver can't send

**Error.** Found emitting the database module's functions. It stops the run: nothing is written.

## What it means

A procedure has a parameter named `@__proto__`. The mssql driver keeps a request's parameters as keys of an object, where
`__proto__` sets the object's prototype rather than adding a key, so the parameter is never sent: the server reports it
missing when it has no default, and when it has one uses the default without a word, whatever value the caller gave.

## Why haruspex reports it

A function that took the parameter and never sent it would fail at every call, or worse, run every call with the default
in place of the caller's value
([decision 0092](../decisions/0092-a-key-named-proto-is-refused-by-the-typescript-emitters.md)).

## What to do

Rename the parameter in the procedure, and generate again.

## Example

```text
haruspex: error HAR5205: s.p has a parameter named @__proto__, which the mssql driver never sends, since it keeps a request's parameters as keys of an object; rename the parameter.
```

**See also:** [HAR5008](HAR5008.md), which the Zod module reports for the same parameter.
