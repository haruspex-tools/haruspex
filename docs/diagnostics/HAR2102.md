# HAR2102: a JSON path that never finds a value

**Warning.** Found inferring the results. The run goes ahead.

## What it means

A `JSON_VALUE`, `json_query` or `OPENJSON` reads JSON whose shape haruspex knows (built in the procedure, or declared for a
column in the config file), at a path the shape can never have: a key an object doesn't have and can't hold, a key of a string
or an array, or an index past the end of an array of fixed length. It is reported once for each place.

## Why haruspex reports it

Under a lax path, the default, SQL Server gives NULL where the path finds nothing, so the call is always NULL; under a strict
path it is always an error. Either way the path is almost certainly a mistake: a key misspelt, or a schema that has moved on.

## What to do

Check the path against the JSON's shape: the query that builds it, or the column's schema. If the schema is what is out of date,
add the key to it.

## Example

```text
db/p1.sql:1:34: warning HAR2102: json_value(N'{"shelf": 3}', '$.room') reads `$.room`, which the JSON there never has (`$.room` is never there: the object has no key `room`), so it is always NULL under a lax path and an error under a strict one. Check the path against the JSON's shape or schema.
```
