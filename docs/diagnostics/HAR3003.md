# HAR3003: a key is written twice in one object

**Error.** Found reading the config file. It stops the run: nothing is written.

## What it means

An object in the file names a key twice.

## Why haruspex reports it

JSON readers keep one of the two, often the last, so the other would be ignored without a word.

## What to do

Remove one of them, or merge the two.

## Example

```text
haruspex.json:1:97: error HAR3003: objects: The key "objects" is written twice in one object.
```
