# HAR4303: generated names clash

**Error.** Found applying the config file to what was inferred. It stops the run: nothing is written.

## What it means

Two objects would get the same generated name.

## Why haruspex reports it

Two declarations of one name can't both be in the generated module, and numbering one would make a name depend on what
else exists.

## What to do

Give one its own name with an override, give a schema a `prefix`, or add a naming `replace` rule that tells them apart,
as the message suggests. For two procedures of one schema, the message builds the rule from where their names differ (the
`#` one has and the other hasn't, below), and suggests it only once it has checked that the rule parts them; put a word of
your own in place of the one it shows. Where the names are the same once the existing `replace` rules have run, or differ
only in letters or digits, it says that no single rule will do, and suggests an override.

## Example

```text
haruspex.json:1:46: error HAR4303: schemas.lib: "GetBook" would name both the procedure lib.get_book and the procedure lib.get_book#. Generated names must not clash: add a naming "replace" rule for where their names differ (nothing against "#"), such as { "pattern": "#", "with": "_hash_" } with a word of your own for "hash", or give one of them its own name with a "name" override in "procedures".
```
