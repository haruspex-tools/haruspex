# HAR4303: generated names clash

**Error.** Found applying the config file to what was inferred. It stops the run: nothing is written.

## What it means

Two objects would get the same generated name.

## Why haruspex reports it

Two declarations of one name can't both be in the generated module, and numbering one would make a name depend on what
else exists.

## What to do

Give one its own name with an override, give a schema a `prefix`, or add a naming `replace` rule that tells them apart,
as the message suggests. For procedures of one schema, the message names every one that would take the name, builds the rule
from the separators in their names (the `#` one has and the other hasn't, below), and suggests it only once it has checked
that the rule parts them all without giving any other name of the module the same; put a word of your own in place of the one
it shows. Where the names are the same once the existing `replace` rules have run, differ only in letters or digits, or no
single rule parts them all (three names that differ in one character each), it says so, and suggests an override.

A table type's rows are named after the type (`LineListRow`), and no setting names them otherwise; a schema that holds only table
types can't be given a `prefix`, since no procedure of it is selected. So when one side of the clash is a table type's rows, the
message suggests renaming the other side, or failing that, one of the table types.

## Example

```text
haruspex.json:1:46: error HAR4303: schemas.lib: "GetBook" would name both the procedure lib.get_book and the procedure lib.get_book#. Generated names must not clash: add a naming "replace" rule for where their names differ (nothing against "#"), such as { "pattern": "#", "with": "_hash_" } with a word of your own for "hash", or give one of them its own name with a "name" override in "procedures".
```
