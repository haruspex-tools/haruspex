# HAR5007: a result set's name can't be a key

**Error.** Found emitting the Zod module. It stops the run: nothing is written.

## What it means

The IR names a procedure's result set `__proto__`. Named sets are the keys of the procedure's schema, an object, and
`__proto__` as a key of an object sets the object's prototype rather than adding a key.

## Why haruspex reports it

The config file never gives such a name, but an IR is a file anything can write, so a name the module couldn't hold is refused
rather than written as a schema that would lose the set
([decision 0070](../decisions/0070-a-procedure-s-result-sets-are-named-all-or-none.md)).

## What to do

Name the set otherwise, in the config file's `sets` or a query file's `-- @sets`, and generate the IR again.

## Example

```text
haruspex: error HAR5007: A result set of s.p is named __proto__, which as a key of an object sets its prototype rather than adding a key; rename the set.
```
