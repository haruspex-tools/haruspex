# HAR1021: a deployment script can't be read in full

**Warning.** Found reading a project or a DACPAC. The run goes on, and what is written says less.

## What it means

A pre- or post-deployment script, or a file it includes with `:r`, can't be read: it doesn't parse (a sqlcmd command other than
`:setvar` and `:r`, or a variable whose value only the deployment gives), it includes a file through a SQLCMD variable, or a file
it includes isn't there. A deployment script is read for what it changes, since a deployment runs it every time: a check it
turns off, a table it alters, a procedure it alters. What this one does isn't known.

## Why haruspex reports it

A deployment script may change what the model claims, and a guess at what it does could claim what it undoes. So every table,
procedure, function and view whose name appears in the script is read as changed by it, and its shape is unknown
([HAR2003](HAR2003.md), [HAR2006](HAR2006.md)). When not even the names are known (an include that can't be found), every one is.

## What to do

Write the script as plain T-SQL with `:r` includes of files the project holds, or move what it does that isn't a change to the
schema (data, permissions) into a script of its own whose objects no procedure you generate reads.

## Example

```text
db/p2.sql:1:1: warning HAR1021: A deployment script can't be read: p2.sql doesn't parse (Incorrect syntax near ':'.). What it does isn't known, so every table, procedure, function and view it names is doubted.
```
