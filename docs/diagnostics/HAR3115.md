# HAR3115: a column's JSON declared null at its top

**Error.** Found reading the config file. It stops the run: nothing is written.

## What it means

The schema of the JSON a column is declared to hold allows `null` at its top: a `type` with `"null"`, or an `anyOf` with a
branch of `null`.

## Why haruspex reports it

A column read as text is JSON text, which the IR types by what a non-null string parses to; it can't say yet that the string
may be the text `null`. Reading the schema without `null` would refuse a value the declaration allows, so the declaration is
refused instead. A column that holds no value is NULL in SQL, which its own nullability already says.

## What to do

Leave `null` out of the schema's top, if the column never holds the text `null`; its NULLs are typed from the column. A key
inside the JSON may still be `null`.

## Example

```text
schemas/extra.schema.json:1:1: error HAR3115: allows the JSON null at its top, which haruspex can't type in a column's text yet. A column with no value is NULL in SQL, which its own nullability says, so leave "null" out here.
```
