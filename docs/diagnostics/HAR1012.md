# HAR1012: a reference to a database on another server isn't read

**Note.** Found reading a project file or a DACPAC. The output stands.

## What it means

The project or package being read refers to a database on another server: a reference that names a server as well as a
database (`ServerSqlCmdVariable` in the project file; `ExternalParts` of two parts, `[$(Annexe)].[$(Archive)]`, in a package).
It isn't read. From a project, it is said once for every project that makes the same reference.

## Why haruspex reports it

A body reaches a database on another server only by a four-part name (`[$(Annexe)].[$(Archive)].dbo.loan`), and haruspex binds
no four-part name: what is on another server is known only when it is deployed. So a name in it is unknown, as it would be
without the reference, and this says why the reference made no difference. A three-part name with the database alone isn't
taken for it either: the build leaves such a name unresolved, since it names a database on the server the procedure runs on.

## What to do

Nothing, unless a procedure you generate reads that server. Then declare its results in the config file
([Configuration](../configuration.md), "Declared results"), since nothing on another server can be inferred.

## Example

```text
db/db.sqlproj:5:15: note HAR1012: db.sqlproj refers to the project ..\archive\archive.sqlproj, the database $(Archive) on the server $(Annexe), which isn't read: a name in it, which a body writes in four parts, stays unknown.
```
