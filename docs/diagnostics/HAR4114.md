# HAR4114: a JSON Schema named in the SQL that disagrees with the config

**Error.** Found applying the config file to the project. It stops the run: nothing is written.

## What it means

A table's column is declared to hold JSON twice: by `columns` in the config file, and by the extended property
`haruspex.jsonSchema` on the column in the SQL. The two name different schemas: another file, or another pointer inside one.

## Why haruspex reports it

A column's JSON has one shape. Taking either declaration would type the column by one and ignore the other, which may be the
one its writers follow, so haruspex takes neither.

## What to do

Declare the column in one place, or name the same file and pointer in both. Two files of the same text are still two schemas:
the IR records the file, and `check` reports a change to it.

## Example

```text
db/p2.sql:1:1: error HAR4114: lib.book.extra is declared to hold JSON of schemas/extra-v2.schema.json here and of schemas/extra.schema.json in the config file, at columns["lib.book.extra"]: declare it once, or name the same schema in both.
```
