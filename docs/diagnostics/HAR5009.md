# HAR5009: a column the driver can't hand over

**Error.** Found emitting the Zod module. It stops the run: nothing is written.

## What it means

A procedure returns rows with a column named as a member every JavaScript object inherits, such as `constructor`, `toString`
or `valueOf`. The mssql driver builds each row by reading the column's name on it first, to find a column repeated, and every
object already has these members, inherited. So it takes the column for a repeated one and hands over an array, the inherited
member and then the value, rather than the value.

## Why haruspex reports it

A schema of the column's value would reject every row the driver hands over
([decision 0092](../decisions/0092-a-key-named-proto-is-refused-by-the-typescript-emitters.md)). The same name as a key of JSON
(`FOR JSON`, `json_object`) is a key like any other, and isn't refused.

## What to do

Name the column otherwise in the SQL (`AS constructor_id`), and generate again.

## Example

```text
haruspex: error HAR5009: The type Row, which s.p returns as rows, has a column named constructor, which the mssql driver hands over as an array of the member every object inherits and the value; name it otherwise in the SQL.
```

**See also:** [HAR5008](HAR5008.md), for a key named `__proto__`.
