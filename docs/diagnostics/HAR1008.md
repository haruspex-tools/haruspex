# HAR1008: part of a project file isn't read

**Warning.** Found reading a project file. The run goes on, and what is written says less.

## What it means

Something in the project file, or a file it imports, isn't evaluated or isn't understood, and it touches what haruspex reads:
which scripts are built, the settings a script starts with, or the database's settings. That part isn't read. The message
names what isn't evaluated (a property function, a property defined nowhere, an item list, a condition, `Choose`, an import,
a target) and where it is. Something else in the file that isn't evaluated says nothing when it touches none of these.

## Why haruspex reports it

A project file is read without MSBuild, so only what [decision 0044](../decisions/0044-a-project-file-is-evaluated-in-part-and-the-rest-reported.md) lists is evaluated. A value
that isn't evaluated could be anything, and a guess would type the database from a list of scripts, or a collation, that isn't
the build's. So nothing it decides is read, and this says so. A project that builds differently as
`Release` than as `Debug` is reported the same way, naming what differs; it is read as `Debug`, as `dotnet build` builds
it unless told otherwise.

## What to do

Write the part the message names plainly: a property defined in the project or a `Directory.Build.props` it imports, a
path without a property function, a condition on `$(Configuration)` rather than a function of the machine. If the part can't
change, read the DACPAC the project builds instead.

## Example

```text
db/db.sqlproj:5:19: warning HAR1008: DefaultCollation, a setting of the database, isn't read: $(LibraryCollation) is defined nowhere in the project or the files it imports, so a build would take it from the environment or its command line, if from anywhere.
```

**See also:** [Decision 0044](../decisions/0044-a-project-file-is-evaluated-in-part-and-the-rest-reported.md), [Configuration](../configuration.md), "Reading a project file".
