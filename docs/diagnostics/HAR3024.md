# HAR3024: a module that can't be named so

**Error.** Found reading the config file, or applying its `split` to the selected procedures and query files. It stops the
run: nothing is written.

## What it means

A module's name names its files (`sales.zod.ts`), and this one can't: it doesn't start with a letter, has a character other
than a letter, a digit, `_` or `-`, is `shared` in any case, or differs from another module's name only in case. With
`"split": "schema"` the module's name is its schema's, so a schema named so can't be a module of its own.

## Why haruspex reports it

A name that isn't a plain file name would write a file somewhere else or nowhere; `shared` is the name of the files that hold
what modules share; and two names that differ only in case would be one file on a file system that ignores case, as macOS's
and Windows' do by default
([decision 0074](../decisions/0074-a-config-may-split-its-output-into-modules.md)).

## What to do

Name the module otherwise. For a schema whose name can't be a module's, list the modules instead, giving its module a name of
its own: `"split": { "lending": ["lending desk"] }`.

## Example

```text
haruspex.json:1:88: error HAR3024: split["lending desk"]: 'lending desk' can't name a module: a module's name starts with a letter and has only letters, digits, '_' and '-', since it names the module's files.
```
