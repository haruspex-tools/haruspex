# HAR2103: the callers' UNMASK isn't applied

**Warning.** Found inferring the results. The run goes ahead.

## What it means

The config file's `session` declares `"unmask": true`, that the callers hold the `UNMASK` permission, but a procedure, function or
trigger of the project is declared `WITH EXECUTE AS` someone other than its caller (`OWNER`, `SELF` or a user). It is reported
once, at the first such module.

## Why haruspex reports it

A module declared so runs with that user's permissions, not the callers', and so does whatever it calls. Whether a masked
column gives its values or its mask then depends on that user's `UNMASK`, which the config file doesn't say. Since haruspex doesn't
follow which procedures reach such a module, it keeps every mask: each masked column, and each value computed from one,
claims only its type, whether it may be null and its greatest length, as it does without the declaration.

## What to do

Nothing, if the claims are enough. Otherwise, check whether the module needs `EXECUTE AS`; without it, the callers' `UNMASK`
decides, and the declaration applies.

## Example

```text
db/p1.sql:1:1: warning HAR2103: The session declares that the callers hold UNMASK, but lib.p runs WITH EXECUTE AS another user, whose permissions decide what it and whatever it calls read, so masked columns are still read as masked everywhere.
```
