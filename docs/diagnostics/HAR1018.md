# HAR1018: a query file's sets comment can't be taken

**Error.** Found reading the SQL. It stops the run: nothing is written.

## What it means

A line comment in a query file that starts `@sets` names the file's result sets, in order and between commas, as
`-- @sets order, lines`, and this one can't be taken: it names no set, leaves a name out between two commas, or is the
file's second such comment.

## Why haruspex reports it

The names are the keys the file's function returns its sets under, so a comment taken wrongly, or passed over, would give the
function another shape than the one meant
([decision 0070](../decisions/0070-a-procedure-s-result-sets-are-named-all-or-none.md)).

## What to do

Write one comment, `-- @sets` and a name for each set the file returns, in order, between commas. A comment that only mentions
the sets shouldn't start with `@sets`.

## Example

```text
sql/q.sql:2:1: error HAR1018: -- @sets titles: the sets are named already, at line 1; name them once.
```
