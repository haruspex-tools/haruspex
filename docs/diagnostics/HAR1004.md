# HAR1004: elements of a DACPAC that aren't modelled

**Note.** Found reading a DACPAC. The output stands.

## What it means

The DACPAC holds elements of kinds haruspex doesn't read into its model, counted by kind (`SqlAssembly`, for example).
Each is passed over.

## Why haruspex reports it

A DACPAC's `model.xml` has no published specification, and a newer DacFx may write kinds of element haruspex has never
seen. Every element is read, passed over for a reason the reader states (permissions, storage, documentation and other
things that change no shape haruspex claims), or counted here, so none is lost in silence. A procedure that uses something
not modelled, such as a parameter of a CLR type, says so as an unknown.

## What to do

Nothing, unless a kind listed is one your procedures rely on and you'd expect haruspex to read; then it is worth an issue.

## Example

```text
kiln-clr-extract.dacpac: note HAR1004: kiln-clr-extract.dacpac holds elements haruspex doesn't model, which are passed over: 1 SqlAssembly.
```
