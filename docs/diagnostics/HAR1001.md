# HAR1001: the SQL doesn't parse

**Error.** Found reading the SQL files. It stops the run: nothing is written.

## What it means

A `.sql` file in the source folder has a syntax error where the line and column point, as SQL Server's own parser
(ScriptDom) reads it. Nothing in that file is read.

It is reported too where haruspex's parser would read a `"…"` otherwise than the server does: after a `SET ANSI_DEFAULTS`
that changed `QUOTED_IDENTIFIER` earlier in the same batch, or after a `SET QUOTED_IDENTIFIER` in a procedure's or trigger's
body, which the server ignores. Every other `SET QUOTED_IDENTIFIER` is followed as the server follows it
([decision 0112](../decisions/0112-a-script-is-parsed-as-the-server-parses-each-batch.md)).

## Why haruspex reports it

A model built without the file would be missing what it defines, and every result that reads it would be wrong or
unknown. So haruspex stops, and writes nothing.

## What to do

Correct the SQL at the place given. The message is the parser's. If the file is meant for sqlcmd (`:setvar`, `$(Name)`),
haruspex replaces the variables it defines; a script it can't read that way may be one to leave out of the folder. For a
`"…"` after a `SET`, put the `SET QUOTED_IDENTIFIER` in a batch of its own before the definition, where SSMS puts it.

## Example

```text
db/p1.sql:1:34: error HAR1001: Incorrect syntax near 'FROM'.
```
