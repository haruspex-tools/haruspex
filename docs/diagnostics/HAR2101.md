# HAR2101: a write to an object the project doesn't define

**Warning.** Found inferring the results. The run goes ahead.

## What it means

A procedure writes to a table or view the project doesn't define, so a trigger on it, which could return result sets of
its own, can't be seen. It is reported once for each object.

## Why haruspex reports it

SQL Server allows results from triggers unless the server's `disallow results from triggers` option is on, which it
isn't by default, so the results haruspex gives rest on there being no such trigger.

## What to do

Add the object's definition, with its triggers, to the source folder; or, if it has none that return results, leave it,
knowing what the warning says.

## Example

```text
db/p1.sql:1:27: warning HAR2101: audit.trail is written here but is not defined in the project, so a trigger on it, which could return result sets of its own, cannot be seen. SQL Server allows results from triggers unless the server's 'disallow results from triggers' option is on, which it is not by default.
```
