# HAR2025: JSON built as text

**Note.** Found inferring the results. The run goes ahead; a note never changes whether it succeeds.

## What it means

The SQL builds a JSON array by joining text: `'[' + string_agg(…) + ']'`, `concat('[', a, ',', b, ']')`, or `concat_ws` of
quoted literals. Brackets T-SQL writes for itself, such as `'[' + name + ']'` quoting an identifier, are not reported. Where
the SQL alone doesn't show it is JSON, as in `'[' + coalesce(@ids, '') + ']'` over a list a variable holds, the note is given
where it is read as JSON. SQL Server has built JSON itself since 2016 (`FOR JSON`), and builds arrays of values with `json_array` (SQL
Server 2022) and `json_arrayagg` (SQL Server 2025 and Azure SQL). The note is given wherever the construction is written,
whether or not anything reads the text as JSON: it is an inventory of code to modernise.

## Why haruspex reports it

JSON built as text is correct only while every value written into it is: a value in quotes that holds a quotation mark makes
more elements, or ends the array early, and the read still succeeds. Such text is typed only where the server guarantees
its shape ([the inference reference](../../src/Haruspex.SqlServer.Inference/README.md#json-assembled-as-text)), so
elsewhere it is unknown. The constructors escape every value, and haruspex types what they build exactly.

## What to do

Where the code can be changed, build the same JSON with a constructor: `json_arrayagg(x ORDER BY …)` for an aggregate,
`json_array(a, b, …)` for a fixed list (it leaves out a NULL, as `concat_ws` does), or `FOR JSON`. Over no rows
`json_arrayagg` is NULL, as `string_agg` is, so keep the `coalesce(…, '[]')` that the text form has. Where it can't be changed,
the note only says where it is.

## Example

```text
db/p1.sql:1:34: note HAR2025: N'[' + string_agg(convert(nvarchar(max), b.id), N',') + N']' builds a JSON array as text; build it with json_arrayagg(…) (SQL Server 2025, Azure SQL), which escapes each value and which haruspex types exactly. Like string_agg, it is NULL over no rows.
```
