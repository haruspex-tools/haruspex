# HAR6040: a listed path generate doesn't remove

**Warning.** Found by `haruspex generate`, going through the list of the files the last run wrote. The run goes on.

## What it means

`haruspex.files.json` names a path, no longer written, that could be outside the output folder: an absolute path, one that
climbs out with `..`, one with a character no name `generate` writes has (it writes ASCII letters, digits, `.`, `-` and `_`,
names joined by `/`), or one reached through a symbolic link. `generate` never removes it,
and writes the list anew without it.

## Why haruspex reports it

`generate` writes only plain files inside its output folder, named alone, so it never writes such an entry: the list was edited,
or written by something else. A name with another character could also name, on a file system that folds it, a file this run
wrote. A file outside the folder is never one of its outputs, and a link may lead anywhere, so it is
left alone, and the warning says why rather than passing over it.

## What to do

Find out how the entry got there. If it names a file of the last run's, remove the file yourself. Don't edit the list: it is
generated.

## Example

```text
out/haruspex.files.json: warning HAR6040: "../notes.ts" climbs out of the output folder, so it isn't removed: generate removes only files inside the output folder, named as it writes them. The list was edited, or written by something else; it is written anew without it.
```
