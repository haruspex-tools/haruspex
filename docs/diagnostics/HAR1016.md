# HAR1016: a query file uses a variable before declaring it

**Error.** Found reading the SQL. It stops the run: nothing is written.

## What it means

A query file uses a variable before the `DECLARE` of it, in the order of the text. SQL Server compiles a batch's declarations,
so one in a branch that never runs still declares the variable, but only for the rest of the batch: a use before it is refused
(error 137). And had haruspex taken the earlier use for a parameter, the call would declare the name twice, which is refused too
(error 134). The file can't run either way.

## Why haruspex reports it

A function for a file that can't run would fail on every call; the problem is the file's, and it is found before any call.

## What to do

Move the `DECLARE` above the first use, or give the parameter and the variable different names.

## Example

```text
sql/q.sql:1:8: error HAR1016: @x is used before the DECLARE of it, which SQL Server refuses (error 137); declare it first, or rename one of them.
```
