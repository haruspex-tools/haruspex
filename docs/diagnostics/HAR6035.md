# HAR6035: a procedure in only one of the two databases

**Warning.** Found by `haruspex generate` with a baseline, and by `haruspex check` with one (unless `--fit-only`). The run goes
on.

## What it means

A procedure is selected in the source but the baseline's database doesn't have it, or the other way round. The module leaves it
out: one only the source has can't be called before the change is deployed, and one only the baseline has can't be called
after.

## Why haruspex reports it

Combined types work against both databases, and no function can call a procedure one of them lacks. Leaving it out turns a call
that would fail at run time into one that doesn't compile, and saying so explains why its function isn't there.

## What to do

For a new procedure, deploy it first; once the baseline has moved on to a release with it, its function is written. For one
being removed, stop calling it.

## Example

```text
db/p1.sql:3:1: warning HAR6035: lib.count_books: the baseline's database doesn't have it, so the application can't call it until the change is deployed; the module leaves it out until the baseline moves on.
```
