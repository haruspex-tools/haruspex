# HAR1022: names that differ only in case

**Error.** Found reading the SQL. It stops the run: nothing is written.

## What it means

Two names in one namespace differ only in case: two columns of one table or table type (`[Code]` and `[code]`), two objects of a
schema of different kinds (a table `dbo.Item` and a view `dbo.ITEM`), or, in one procedure, function, trigger or query file, two
parameters or variables (`@Total` and `@total`), two temporary tables (`#t` and `#T`), or two columns of a table it declares.

SQL Server refuses such a pair wherever names are compared without case: a database's collation decides for its tables'
columns and its objects, and the server's for variables, temporary tables and the tables a body declares (errors 2705, 2714
and 134). So the pair can exist only under a case-sensitive collation, where the two are different names.

## Why haruspex reports it

Names are matched ignoring case. For every project that deploys, that gives what SQL Server's matching gives, except
where one namespace holds two names that differ only in case: there a reference to either would be read as the other, with
the other's type, nullability and `CHECK` constraints. Rather than guess which one is meant, haruspex stops
([decision 0119](../decisions/0119-names-that-differ-only-in-case-are-an-error.md)).

## What to do

Rename one of the two, so that their names differ in more than case. Two objects of one kind whose names differ only in case
are [HAR1002](HAR1002.md).

## Example

```text
db/p1.sql:1:46: error HAR1022: lib.p declares the variables @Total (p1.sql:1:24) and @total (p1.sql:1:46), whose names differ only in case: haruspex matches names without case, so it can't tell them apart.
```
