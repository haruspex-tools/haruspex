# HAR1019: a query file's module comment can't be taken

**Error.** Found reading the SQL. It stops the run: nothing is written.

## What it means

A line comment in a query file that starts `@module` names the module the file belongs to when the config file splits its
output, as `-- @module reports`, and this one can't be taken: it names no module, names more than one word, or is the file's
second such comment. It is an error whether or not the config file splits its output: a query file is read the same either way,
as its `-- @sets` comment is.

## Why haruspex reports it

The module decides which files the query file's schema and function are written to, so a comment taken wrongly, or passed
over, would put them where nobody meant, and a file that reads differently once `split` is added would fail only then
([decision 0074](../decisions/0074-a-config-may-split-its-output-into-modules.md)).

## What to do

Write one comment, `-- @module` and the module's name, a single word. A comment that only mentions a module shouldn't start
with `@module`.

## Example

```text
sql/q.sql:1:1: error HAR1019: -- @module lending desk: the module is named by one word, such as -- @module reports.
```
