# HAR6015: the committed module isn't what haruspex writes

**Error.** Found by `haruspex check`, comparing with what is committed. The check fails, with exit code 1, and nothing is
written.

## What it means

The committed IR claims the same as what haruspex infers, but the committed `haruspex.zod.ts` isn't the module haruspex
writes for it. Line endings are set aside.

## Why haruspex reports it

Another version of haruspex wrote it, or it was edited by hand. Either way the module applications compile against isn't
the one generated from the contract, so it is reported rather than passed.

## What to do

Run `haruspex generate`, read the change to the module (`git diff`), and commit it. Don't edit generated files: change the
SQL or the config file instead.

## Example

```text
out/haruspex.zod.ts: error HAR6015: this module isn't what haruspex writes for the IR beside it, though the IR claims the same: another version of haruspex wrote it, or it was edited. Run haruspex generate, and read the change to the module before committing it.
```
