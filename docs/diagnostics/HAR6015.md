# HAR6015: the committed module isn't what haruspex writes

**Error.** Found by `haruspex check`, comparing with what is committed. The check fails, with exit code 1, and nothing is
written.

## What it means

The committed IR claims the same as what haruspex infers, but the committed `haruspex.zod.ts` isn't the module haruspex
writes for it. The message quotes the first line that differs, as committed and as haruspex writes it now. Line endings are
set aside.

## Why haruspex reports it

The module says more than the claims `check` compares: its comments give the reason a value is unknown, and the reason a
result may be absent (no rows, or a statement that may not run), and a reader acts on them. So a change to the SQL that
changes only a reason changes the module, and so does a module another version of haruspex wrote, or one edited by hand.
Whichever it is, the module applications compile against isn't the one generated from the database, so it is reported
rather than passed.

## What to do

Run `haruspex generate`, read the change to the module (`git diff`), and commit it. Don't edit generated files: change the
SQL or the config file instead.

## Example

```text
out/haruspex.zod.ts: error HAR6015: line 28 is `// edited` where haruspex now writes nothing (the module ends before), though no claim the IR makes has changed. A comment written from a reason (why a value is unknown, why a result may be absent) changes so; so does a module another version of haruspex wrote, or one edited. Run haruspex generate, and read the change to the module before committing it.
```
