# HAR5101: one name for two definitions

**Error.** Found emitting the JSON Schema document. It stops the run: nothing is written.

## What it means

One name in the IR is given to two things the document defines: a procedure and a named type, or two procedures.

## Why haruspex reports it

The document holds every procedure's results and every named type in one `$defs`, by name
([decision 0051](../decisions/0051-one-json-schema-document-per-module-every-value-as-json.md)), so one name can key only one
of them. The names haruspex settles never clash ([HAR4303](HAR4303.md) says so when they would), so this comes from an IR file
written by something else.

## What to do

From `haruspex generate`, which writes its own IR, this is a fault in haruspex: please report it as an issue, with the SQL
that gave it. From a program that hands the emitter an IR of its own, give each procedure and type a name of its own in that
IR.

## Example

```text
haruspex: error HAR5101: The IR name 'GetBasket' names a type and the procedure shop.get_basket, which one $defs can't hold.
```
