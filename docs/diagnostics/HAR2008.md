# HAR2008: a table the project doesn't define

**Note.** Found inferring the results. The run goes ahead; a note never changes whether it succeeds.

## What it means

A table, view or function the project doesn't define. The value, or the result, is unknown in the output, with this
reason, and the generated schema accepts anything there.

## Why haruspex reports it

The output never claims more than SQL Server guarantees: what haruspex can't prove, it says it doesn't know, so the
output stays true. The note says where, so that an unknown is never silent.

## What to do

Add its definition to the source folder. A table in another database can't be added; override the value's type in the
config file.

## Example

```text
db/p1.sql:1:34: note HAR2008: lib.p results[0][].a: There is no table lib.missing in the project.
```
