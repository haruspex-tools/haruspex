# HAR5206: an xml OUTPUT parameter the driver can't receive

**Warning.** Found emitting the database module's functions. That procedure's function is left out; the rest of the module is
written, and the run goes ahead.

## What it means

A procedure has an `OUTPUT` parameter of type `xml`, typed by a schema collection or not. The mssql driver, as of 12.7.14, can't
receive one: it declares the parameter as `nvarchar`, so bound as the driver's `sql.Xml()`, or as `sql.NVarChar(sql.MAX)`, the
server fails the call with error 257, "Implicit conversion from data type xml to nvarchar is not allowed".

## Why haruspex reports it

A function that bound the parameter would fail at every call, so the database module has none for the procedure. The IR still
types the parameter, since what the procedure holds in it is the server's claim; only the driver can't hand it over. The other
procedures' functions don't depend on it, and are written.

## What to do

Return the XML in a result set, where the driver hands it over as text, or make the parameter `nvarchar(max)` and convert the
XML to it in the procedure. Then generate again. A later driver that receives `xml` would need this observation repeated.

## Example

```text
haruspex: warning HAR5206: shop.describe_product has an xml OUTPUT parameter, @spec, which the mssql driver (12.7.14) can't receive: the call fails with error 257 however it is bound, so the module has no function for it. Return the XML in a result set instead, or convert it to nvarchar(max) in the procedure.
```
