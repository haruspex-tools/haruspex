# HAR5206: an xml OUTPUT parameter the driver can't receive

**Error.** Found emitting the database module's functions. It stops the run: nothing is written.

## What it means

A procedure has an `OUTPUT` parameter of type `xml`, typed by a schema collection or not. The mssql driver can't receive one:
bound as the driver's `sql.Xml()`, or as `sql.NVarChar(sql.MAX)`, the server fails the call with error 257, "Implicit conversion from data
type xml to nvarchar is not allowed".

## Why haruspex reports it

A function that bound the parameter would fail at every call. The IR still types the parameter, since what the procedure
holds in it is the server's claim; only the driver can't hand it over.

## What to do

Return the XML in a result set, where the driver hands it over as text, or make the parameter `nvarchar(max)` and convert the
XML to it in the procedure. Then generate again.

## Example

```text
haruspex: error HAR5206: shop.describe_product has an xml OUTPUT parameter, @spec, which the mssql driver can't receive: the call fails with error 257 however it is bound. Return the XML in a result set instead, or convert it to nvarchar(max) in the procedure.
```
