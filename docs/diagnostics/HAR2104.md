# HAR2104: a declared result column narrower than the callee's

**Warning.** Found inferring the results. The run goes ahead.

## What it means

An `EXEC … WITH RESULT SETS` declares a column that doesn't hold every value of the callee's column it receives. Each value
arrives converted to the declared type, so some of the callee's values change or fail the call:

- a string or binary value longer than the declared column is cut short, silently;
- a `tinyint`, `smallint` or `int` that may be too long for a declared `char` or `varchar` is written `*`, and any other number
  too long for a declared string, an `nchar` or `nvarchar` included, fails the call (8114);
- a number that may be past a declared numeric type's range fails the call (8114);
- a type the callee's can't convert to at all fails every call that returns a row there (11538);
- a column declared `NOT NULL` over one that may be null fails the call when a NULL arrives (11553).

It is reported once for each column, where the callee is a procedure of the project and its column's type is known.

## Why haruspex reports it

The declaration still types the call, since the server enforces it: the TypeScript says what arrives. But a value cut short
or written `*` is rarely what was meant, and a call that fails on some rows is an error waiting for the data that makes it.
A decimal rounded to fewer places, a date or time to fewer fractional digits, and national text into a code page that lacks
some of its characters aren't reported: each value still arrives, close to the callee's.

## What to do

Declare a type that holds every value the callee returns, such as the callee's own type, or convert the value in the callee
where losing part of it is intended, so the conversion is written where it happens.

## Example

```text
db/p2.sql:1:27: warning HAR2104: EXEC lib.q WITH RESULT SETS declares id varchar(3), column 1 of result set 1, over lib.q's id: a value of int may not fit, so it is written *. Declare a type that holds every value, or convert it in lib.q.
```
