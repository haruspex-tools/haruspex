# HAR2009: a column that can't be found or is ambiguous

**Note.** Found inferring the results. The run goes ahead; a note never changes whether it succeeds.

## What it means

A column that isn't in the tables in scope, or that more than one of them has. The value, or the result, is unknown in
the output, with this reason, and the generated schema accepts anything there.

## Why haruspex reports it

The output never claims more than SQL Server guarantees: what haruspex can't prove, it says it doesn't know, so the
output stays true. The note says where, so that an unknown is never silent.

## What to do

Qualify the column with its table's alias, or correct its name.

## Example

```text
db/p1.sql:1:34: note HAR2009: lib.p results[0][].gone: The table lib.book has no column nope.
```
