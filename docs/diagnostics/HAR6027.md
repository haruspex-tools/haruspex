# HAR6027: a change the running application ignores

**Warning.** Found by `haruspex check` with a baseline. The check goes on.

## What it means

The database being checked has something the application built against the baseline doesn't know, and sets aside: a key its
schema doesn't list (stripped, [decision 0008](../decisions/0008-objects-strip-unknown-keys-by-default.md)), a result set
after those its functions read ([decision 0063](../decisions/0063-a-function-ignores-result-sets-after-those-it-knows.md)),
or a parameter it doesn't send, which has a default.

## Why haruspex reports it

The change is safe for the application already running, but it doesn't see it until it is redeployed, which is worth knowing
while the two differ. Under `"objects": "strict"` the application refuses a key or a set it doesn't know, so the same change is
[HAR6026](HAR6026.md) instead.

## What to do

Nothing, if the change is meant. The warning ends when the baseline moves on to a release that has it.

## Example

```text
db/p1.sql:1:1: warning HAR6027: lib.get_book results[0][].extra: added (string, nvarchar(max), nullable), and the application's schema strips a key it doesn't list. The application already running sets it aside until it is redeployed.
```
