# HAR3002: the config file isn't JSON

**Error.** Found reading the config file. It stops the run: nothing is written.

## What it means

The config file, or a schema file it names, isn't JSON, even allowing the comments and trailing commas the file may
have. The message is the JSON reader's, but for three cases said in the file's own terms: a file that is empty, one that holds
only white space and comments, and one in UTF-16 or UTF-32 rather than UTF-8, which Windows PowerShell 5 writes with `>` and
`Out-File`.

## Why haruspex reports it

A file that can't be read can't be checked or applied.

## What to do

Correct the JSON at the place given. A file in UTF-16 or UTF-32 is saved again as UTF-8: in Windows PowerShell 5, with
`Set-Content -Encoding utf8` or an editor's "Save with encoding".

## Example

```text
haruspex.json:1:13: error HAR3002: Expected depth to be zero at the end of the JSON payload. There is an open JSON object or array that should be closed.
```
