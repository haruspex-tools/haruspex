# HAR2003: an object whose definition depends on the order of scripts

**Note.** Found inferring the results. The run goes ahead; a note never changes whether it succeeds.

## What it means

An object is defined by statements whose order decides which applies, such as a `CREATE` and an `ALTER`, or a definition
and a `DROP`. The value, or the result, is unknown in the output, with this reason, and the generated schema accepts
anything there.

## Why haruspex reports it

The output never claims more than SQL Server guarantees: what haruspex can't prove, it says it doesn't know, so the
output stays true. The note says where, so that an unknown is never silent.

## What to do

Keep one definition of the object in the folder.

## Example

```text
db/p2.sql:1:1: note HAR2003: lib.p results: lib.p is changed by ALTER PROCEDURE at p2.sql:1:1, and which definition applies depends on the order the scripts run.
```
