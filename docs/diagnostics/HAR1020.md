# HAR1020: a script or folder can't be read

**Error.** Found reading the SQL. Nothing in that script or folder is read.

## What it means

A script, or a folder of scripts, is there but can't be read: a link to a file that isn't there, a file or folder the user
running haruspex may not open, or a file another program holds open and won't share (as Windows holds one an editor or a
backup has open). A folder the project's pattern names (`**/*.sql`) that can't be entered is reported the same way.

## Why haruspex reports it

What the script defines, or what it changes, is missing from the model, so the output may claim what that script would
have taken away. The problem is the input's, not haruspex's, so it is an error with the file's name, not a fault.

## What to do

Remove the link or point it at a file that is there, give the user read access, or close the program that holds the file,
and run again.

## Example

```text
db/p2.sql:1:1: error HAR1020: p2.sql can't be read, so nothing in it is: it can't be opened, as when another program holds it.
```
