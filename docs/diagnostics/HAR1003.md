# HAR1003: a referenced DACPAC isn't found

**Warning.** Found reading a DACPAC. The run goes on, and what is written says less.

## What it means

The DACPAC being read refers to another (a database reference in its project), and no file of that name was found in any
place haruspex looks: beside the package that refers to it, in each folder the config file's `references` names, and at the
path recorded when the package was built. The message lists every place, in the order looked.

## Why haruspex reports it

A reference to a package of the same database means part of the database is in that package. Without it, a table, view,
function or procedure it defines is missing from what haruspex reads, so whatever uses one is unknown; each such unknown
says the name may be defined in the missing package. Saying it once here sends you to the one cause rather than to each
name. A reference to another database's package, or to `master.dacpac`, is recorded in the IR as not found.

## What to do

Build the referenced project, so its DACPAC is in the referring project's `bin` folder as a build leaves it, or name the
folder that holds it in `references` in the config file. The IR's `source.references` lists each package read, with its
SHA-256, so you can see which copy was used.

## Example

```text
crane.dacpac: warning HAR1003: crane.dacpac refers to quay.dacpac, a package of the same database, which isn't found: looked for at quay.dacpac, /tmp/tmp.m6Q5SKYaDN/projects/quay/bin/Debug/quay.dacpac. Put it beside crane.dacpac, or name its folder in "references" in the config file.
```
