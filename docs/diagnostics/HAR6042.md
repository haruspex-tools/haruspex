# HAR6042: a file generate would remove

**Error.** Found by `haruspex check`, comparing with the files in the output folder. The check fails, with exit code 1, and
nothing is written.

## What it means

The list of the files the last run of `generate` wrote, `haruspex.files.json`, names this file, and `generate` wouldn't write it
now: a module taken out of `split`, or emptied, or an emitter taken off `emit`. The next run of `generate` removes it.

## Why haruspex reports it

The file no longer matches the IR. An application that imports it compiles against a module that is gone, and may still
compile against a newer shared file, then fail at run time.

## What to do

Run `haruspex generate`, which removes it, and commit the removal with the rest of the change.

## Example

```text
out/old.zod.ts: error HAR6042: generate wrote this file last and doesn't write it now, so the next run removes it. Run haruspex generate, and commit the removal with the rest.
```

[decision 0050](../decisions/0050-check-compares-claims-not-files.md) for what `check` compares.
