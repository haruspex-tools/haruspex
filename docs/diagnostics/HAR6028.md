# HAR6028: a function's return shape changes

**Warning.** Found by `haruspex check` with a baseline, when the config file's `emit` names `mssql`. The check goes on.

## What it means

A procedure's generated function returns another shape than it did for the baseline: one result returned itself becoming an
object of several (`{ result1, result2 }`), or one that gained `output` or `returnValue`, or an object that lost a field,
as when a set's name changes in the config file (`{ orders }` becoming `{ rows }`) ([decision 0060](../decisions/0060-a-call-returns-its-one-result-itself.md) says when a function returns its one result
itself).

## Why haruspex reports it

The application already running keeps its own functions, so it is unaffected; but each call of the function changes when the
application is next built against the new module, which is worth knowing before the change is made rather than when the
build fails.

## What to do

Change the calls in the same release as the module. A procedure whose result sets are named returns the same object whatever
sets it gains, so a set added later doesn't change its shape.

## Example

```text
db/p1.sql:1:1: warning HAR6028: lib.get_book: its function now returns { result1, result2 } where it returned the result itself, so each call of it changes when the application is next built; the application already running is unaffected. A procedure whose result sets are named returns the same object whatever sets it gains.
```
