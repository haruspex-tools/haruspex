# HAR2024: a query file's parameter its uses don't decide

**Note.** Found inferring the results. The run goes ahead; a note never changes whether it succeeds.

## What it means

A query file uses a variable without declaring it, so it is a parameter, and nothing in the file decides its type: none of its
uses is one haruspex infers a type from (a comparison with a column or a literal, arithmetic with one, a count of rows, a column
it is assigned to, a procedure's or function's parameter, each where the server's type for it has been observed), or the uses
that are decide different types. The parameter is unknown in the output, with
this reason, and so is any value that comes from it.

## Why haruspex reports it

Each rule haruspex types a parameter by is the one SQL Server's `sp_describe_undeclared_parameters` follows, observed use by
use. Where no rule decides, or two decide differently, a type would be a guess, and the generated function would check values
against it. The note says where, so that an unknown is never silent.

## What to do

Declare the parameter in the file, on a line of its own, as `DECLARE` would declare it:

```sql
-- @param @label nvarchar(40)
SELECT @label AS label;
```

Read [decision 0059](../decisions/0059-a-query-file-s-parameters-are-typed-from-their-uses.md) for which uses decide a type.

## Example

```text
sql/q.sql:1:8: note HAR2024: sql/q.sql parameters.@label: No use of @label decides its type: none is one that haruspex infers a type from. Declare it in the file: -- @param @label <type>.
```
