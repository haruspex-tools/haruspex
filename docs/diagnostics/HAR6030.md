# HAR6030: the baseline can't be read

**Error.** Found by `haruspex check` or `haruspex generate`, reading its baseline. The run fails, with exit code 1.

## What it means

The baseline is an IR file this haruspex can't read: written by a version that writes another IR version, or not IR at all.

## Why haruspex reports it

A claim's meaning may change between IR versions, so an IR of another version isn't compared claim by claim
([decision 0024](../decisions/0024-an-ir-reader-reads-only-versions-whose-documents-mean-what-its-own-do.md)).

## What to do

Give the baseline as the source it was inferred from (the release's `.dacpac`, its `.sqlproj` or its folder of scripts), which
this version reads as it reads the source. An IR file is the right baseline while the running application and the check use
the same version of haruspex.

## Example

```text
haruspex: error HAR6030: the baseline release.ir.json is IR 0.9, and this haruspex reads IR 0.35, 0.34, 0.33, 0.32, 0.31, 0.30, 0.29, 0.28, 0.27, 0.26, 0.25, 0.24 and 0.23, so the two can't be compared claim by claim. Give the baseline as the source it was inferred from (a .dacpac, a .sqlproj or a folder), which this version reads.
```
