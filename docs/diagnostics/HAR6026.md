# HAR6026: a change the running application would fail on

**Error.** Found by `haruspex check` with a baseline. The check fails, with exit code 1, and nothing is written.

## What it means

The database being checked differs from the baseline, the database the application already running was built against, in a
way that application would fail on. One error for each change, at its procedure, said as the change: a value its schemas
refuse (a key removed, made nullable or left out; a type, length, range or value set widened; a result set removed or made
optional), or a call the procedure refuses (a parameter added without a default, removed, narrowed or no longer an output
parameter; a procedure gone).

## Why haruspex reports it

An application and its database deploy separately, so for a while the application already running meets the database being
deployed. A change it fails on breaks it in production until it is redeployed, which is the failure this check exists to
catch before the deploy.

## What to do

Ship the change in two steps (expand, then contract): first a change the running application can take, such as a new column
beside the old one or a parameter with a default, and the rest once every application has been redeployed and the baseline
has moved on. If no running application is built against the baseline any more, move the baseline forward.

## Example

```text
db/p1.sql:1:1: error HAR6026: lib.get_book results[0][].title: removed (string, nvarchar(100)), and the application's schema requires the key. The application already running, built against the baseline, would fail: ship a change it can take first, and this one once it is redeployed.
```
