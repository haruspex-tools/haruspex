# HAR6039: the list of files written can't be read

**Warning.** Found by `haruspex generate`, reading the output folder before it writes. The run goes on.

## What it means

`haruspex.files.json`, the list of the files the last run wrote, is there but can't be read: it isn't JSON, its `"files"`
isn't a list of paths, or the file system refused it. `generate` removes a file of the last run's only when that list names
it, so this run removes none, and writes the list anew with the files it wrote.

## Why haruspex reports it

Removing nothing is safe, but it may leave files of the last run's that this one no longer writes, such as a module taken out
of `split`. They no longer match the IR, and nothing else would say so.

## What to do

Look at the output folder for files of the last run's that this run didn't write, and remove them yourself; the new list is
right from now on. If the list was edited by hand, don't: it is generated.

## Example

```text
out/haruspex.files.json: warning HAR6039: this list of the files the last run wrote can't be read: it isn't JSON, from line 1. So none of them is removed, and the list is written anew with this run's files; remove yourself any file the last run wrote that this one doesn't.
```
