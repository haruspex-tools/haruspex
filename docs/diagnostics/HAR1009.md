# HAR1009: a script a project builds isn't found

**Error.** Found reading a project file. Nothing in that script is read.

## What it means

The project's build reads a script (a `Build` item) that isn't on disk, even ignoring case, or whose path is rooted the
way only Windows roots one (`C:\build\…`) and is read on another system. It is also a pattern, such as the SDK's own
`**/*.sql`, that a build can't expand because a folder under it can't be entered: on Windows, a link or junction to a folder
that isn't there. A build then takes the pattern for a file's name and stops (`SQL72001`).

## Why haruspex reports it

A build of the project would stop here, so what is read can't be what the build gives.

## What to do

Restore the file, or correct or remove the item in the project file. For a pattern, remove the link the message names, or
point it at a folder that is there.

## Example

```text
db/db.sqlproj:5:15: error HAR1009: db.sqlproj builds ..\archive\loans.sql, which isn't there.
```
