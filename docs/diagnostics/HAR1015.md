# HAR1015: a query file's parameter declaration can't be taken

**Error.** Found reading the SQL. It stops the run: nothing is written.

## What it means

A line comment in a query file that starts `@param` declares a parameter's type, as `-- @param @order_id int`, and this one
can't be taken: it isn't a name and a type, its type doesn't read as `DECLARE` would read it, it declares a parameter a second
time, or it names a variable that the file declares itself with `DECLARE`, or doesn't use at all.

## Why haruspex reports it

A declaration that is taken wrongly, or passed over, would give the file's function a parameter of the wrong type, or one that
does nothing. A misspelt name is the usual cause, and it would otherwise leave the parameter it meant typed from its uses.

## What to do

Write the declaration as `-- @param @name type`, one parameter to a line, with the name as the file uses it and the type as
`DECLARE` takes it. A comment that only mentions a parameter shouldn't start with `@param`.

## Example

```text
sql/q.sql:1:1: error HAR1015: -- @param @client_id int: the file doesn't use @client_id, so it isn't a parameter; check its spelling.
```
