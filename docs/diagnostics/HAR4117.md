# HAR4117: a parameter that can't hold declared JSON

**Error.** Found applying the config file to the project. It stops the run: nothing is written.

## What it means

A parameter declared to hold JSON of a schema, by `parameters` or by the extended property `haruspex.jsonSchema` in the SQL, is
not one that can: its procedure or function isn't in the project, it has no such parameter, it is an `OUTPUT` parameter, it is
of a type that can't hold text (only `char`, `varchar`, `nchar`, `nvarchar`, an alias type of one, and `json` can), or it belongs
to a numbered procedure (`get_order;2`).

## Why haruspex reports it

A declaration says what every caller sends, and the body's reads of the parameter take it as given. A parameter that can't hold
JSON text can't be sent any. An `OUTPUT` parameter's value comes back as well as goes, so a declaration of what goes in would be
read as a claim about what comes back. No numbered procedure is read, and SQL Server takes no extended property on one's
parameter, so nothing would read the declaration.

## What to do

Declare a parameter that takes the JSON, correct the name, or remove the declaration.

## Example

```text
haruspex.json:1:93: error HAR4117: parameters["lib.save_book.@copies"]: lib.save_book.@copies is of the type int, which can't hold JSON text: only a string type (char, varchar, nchar, nvarchar) or json can.
```
