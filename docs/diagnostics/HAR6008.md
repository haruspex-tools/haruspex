# HAR6008: the output can't be written

**Error.** Found on the command line, or reading and writing files. It fails the run: nothing more is written, and what was
written before it stays (below).

## What it means

The output couldn't be written: the folder can't be created or written to, or the disk is full. The message is the
system's.

Written after the module, the list of the files `generate` wrote, `haruspex.files.json`, can fail the same way. The module is
then in place and the run says what it wrote, but fails with this error at the list: the next run goes by whatever list is
there, which may not name every file this one wrote
([the files generate removes](../configuration.md#the-files-generate-removes)).

## Why haruspex reports it

Nothing generated is any use unless it is written. The files written so far are put back as they were, so the folder
doesn't hold a new file beside an old one, except in the two cases [the command line's README](../../src/Haruspex.Cli/README.md#what-it-guarantees)
names: a process killed between the two moves, and a file system that refuses to put the IR back, which the message then says.

## What to do

Make the folder writable, or choose another.

## Example

The message ends with what the operating system said, which differs from one to another.

```text
haruspex: error HAR6008: cannot write to out: …
```
