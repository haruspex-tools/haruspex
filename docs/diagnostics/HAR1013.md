# HAR1013: a table whose definition lists no columns isn't read

**Note.** Found reading the SQL. The output stands.

## What it means

A `CREATE TABLE` lists no columns, so the columns it makes aren't in the script: a FileTable (`AS FILETABLE`), whose columns
the server fixes, or a table made from a query (`WITH (…) AS SELECT`), whose columns are the query's. Neither is read,
so the table is passed over, and a name in it is unresolved ([HAR2008](HAR2008.md)).

An edge table may also list no columns (`CREATE TABLE shop.follows AS EDGE`). That one is read: its own columns are none,
and its `SELECT *` gives only the pseudo-columns the server names, which haruspex reports as unknown.

## Why haruspex reports it

A table it can't read is one it can't type, and passing over it in silence would leave the unresolved names that follow
without a reason. A DACPAC's FileTable is passed over in the same way ([HAR1004](HAR1004.md)).

## What to do

Nothing, unless a procedure you generate reads the table. Then declare that procedure's results in the config file
([Configuration](../configuration.md), "Declared results"), or define the table with its columns listed.

## Example

```text
db/p1.sql:1:1: note HAR1013: lib.scan is made from a query, whose columns are the query's; haruspex doesn't read them, so a name in it is unresolved.
```
