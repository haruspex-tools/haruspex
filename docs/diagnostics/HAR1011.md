# HAR1011: a project's reference isn't read yet

**Note.** Found reading a project file. The output stands.

## What it means

The project refers to another database (a `ProjectReference` with `DatabaseVariableLiteralValue`, `DatabaseSqlCmdVariable`
or `ServerSqlCmdVariable`), to a DACPAC (`ArtifactReference`), or to a package (`PackageReference`, such as
`Microsoft.SqlServer.Dacpacs.Master`), and haruspex doesn't read such a reference from a project yet.

## Why haruspex reports it

A name in what it refers to stays unknown, exactly as when the same scripts are read as a folder, and this says why. Reading
these references is planned; a DACPAC's are read already.

## What to do

Nothing, unless a procedure you generate reads another database or a system view; then read the DACPAC the project builds,
which reads these references.

## Example

```text
db/db.sqlproj:5:15: note HAR1011: db.sqlproj refers to the DACPAC ..\archive\archive.dacpac, which isn't read from a project yet: a name in it stays unknown.
```
