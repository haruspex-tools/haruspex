# HAR1011: a project's reference isn't read yet

**Note.** Found reading a project file. The output stands.

## What it means

The project refers to another database (a `ProjectReference` with `DatabaseVariableLiteralValue`, `DatabaseSqlCmdVariable`
or `ServerSqlCmdVariable`), to a DACPAC (`ArtifactReference`), or to a package that holds a DACPAC (`PackageReference`,
such as `Microsoft.SqlServer.Dacpacs.Master`, or one whose folder in the NuGet cache has `tools/*.dacpac`), and such a reference
isn't read from a project yet. A package the cache doesn't have may hold one, so it is noted too; one the cache shows without a
DACPAC, such as a code-analysis rules package, says nothing. Visual Studio's reference to SSDT's own `master.dacpac`
(`$(DacPacRootPath)\…\SqlSchemas\master.dacpac`) is one of these. A reference many projects make (one in a shared `.props`, or SSDT's
`master.dacpac` in each) is said once, with how many projects make it.

## Why haruspex reports it

A name in what it refers to stays unknown, exactly as when the same scripts are read as a folder, and this says why. Reading
these references is planned; a DACPAC's are read already.

## What to do

Nothing, unless a procedure you generate reads another database or a system view; then read the DACPAC the project builds,
which reads these references.

## Example

```text
db/db.sqlproj:5:15: note HAR1011: db.sqlproj refers to the DACPAC ..\archive\archive.dacpac, which isn't read from a project yet: a name in it stays unknown.
```
