# HAR1011: a project's reference isn't read yet

**Note.** **Retired.** It was found reading a project file; haruspex no longer reports it, and its number is never given out
again.

## What it meant

The project referred to another database (a `ProjectReference` with `DatabaseVariableLiteralValue`, `DatabaseSqlCmdVariable` or
`ServerSqlCmdVariable`), to a DACPAC (`ArtifactReference`), or to a package that holds one (`PackageReference`, such as
`Microsoft.SqlServer.Dacpacs.Master`), and a project's reader didn't read such references yet: a name in what it referred to
stayed unknown, as when the scripts are read as a folder.

## Why it is retired

A project's reader reads each of them now, as a DACPAC's reader does
([decision 0045](../decisions/0045-a-project-s-references-are-read-from-where-its-build-takes-them.md)). The one kind still not read, a
database on another server, has a code of its own, [HAR1012](HAR1012.md), which a DACPAC's reference to one gives too. One that
isn't found is [HAR1003](HAR1003.md) or, for a project, [HAR1007](HAR1007.md).

## What to do

Read the diagnostic that took its place, if any is given.

**See also:** [Decision 0036](../decisions/0036-diagnostics-have-stable-codes.md).
