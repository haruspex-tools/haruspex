# HAR3008: a schema has two blocks

**Error.** Found reading the config file. It stops the run: nothing is written.

## What it means

Two blocks of `schemas` name the same schema, their names differing only in case.

## Why haruspex reports it

SQL Server compares schema names ignoring case, so both blocks would apply to the same schema, and which wins would be
arbitrary.

## What to do

Merge the two blocks.

## Example

```text
haruspex.json:1:75: error HAR3008: schemas.LIB: the schema "lib" already has a block, at line 1; schema names are compared ignoring case, as SQL Server compares them. Merge the two.
```
