# HAR2006: a table source that isn't modelled yet

**Note.** Found inferring the results. The run goes ahead; a note never changes whether it succeeds.

## What it means

A table source haruspex doesn't model yet, such as `STRING_SPLIT`. The value, or the result, is unknown in the
output, with this reason, and the generated schema accepts anything there.

## Why haruspex reports it

The output never claims more than SQL Server guarantees: what haruspex can't prove, it says it doesn't know, so the
output stays true. The note says where, so that an unknown is never silent.

## What to do

Rewrite the source as one that is modelled, if you can, or declare the procedure's results in the config file
([Configuration](../configuration.md), "Declared results").

## Example

```text
db/p1.sql:1:34: note HAR2006: lib.p results[0][].value: The table source STRING_SPLIT(N'a,b', N',') AS s is not modelled yet.
```
