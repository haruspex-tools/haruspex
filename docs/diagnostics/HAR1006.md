# HAR1006: an encrypted function or view whose text the DACPAC lacks

**Warning.** Found reading a DACPAC. The run goes on, and what is written says less.

## What it means

A function or view was created `WITH ENCRYPTION`, and the DACPAC holds a placeholder in place of its text, as one extracted
from a database by SqlPackage does: SQL Server gives no one an encrypted module's text. Its return type or columns are in
that text, so it is left out of the model.

## Why haruspex reports it

Whatever reads it can't be typed, and each such place is an unknown; this says why once. An encrypted procedure is read
with its parameters, and its results are an unknown with the reason `encrypted-definition`, since the placeholder would
claim it returns nothing.

## What to do

Read the DACPAC built from the project instead, which keeps the text of every module, encrypted or not. If you only have
the database, declare the results of the procedures that use it in the config file.

## Example

```text
atelier-extract.dacpac/[studio].[secret_kilns]:1:1: warning HAR1006: studio.secret_kilns is encrypted, and the package holds a placeholder, not its text: it is left out, so what reads it is unknown.
```
