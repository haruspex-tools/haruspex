# HAR6013: a file in the output folder can't be read

**Error.** Found by `haruspex check`, comparing with the files in the output folder. The check fails, with exit code 1, and nothing is
written.

## What it means

The `haruspex.ir.json` in the output folder isn't JSON, or isn't an IR document: a property is missing, or has a value the format
doesn't allow. The message says where the reader stopped. Or a file there, the IR or a module beside it, can't be read at all:
the file system refuses it (its permissions, or another process holding it), and the message is the file system's.

## Why haruspex reports it

Nothing can be compared with a file that can't be read. An IR that doesn't read is never what haruspex writes, so it was
edited, or a merge left conflict markers in it.

## What to do

For a file the file system refuses, let haruspex read it (its permissions, or the process holding it). Otherwise run
`haruspex generate` to write it again, and commit it. If a merge broke it, generate from the merged SQL rather than
mending the file by hand.

## Example

```text
out/haruspex.ir.json: error HAR6013: this file can't be read as IR: $.source is missing. Run haruspex generate to write it again.
```
