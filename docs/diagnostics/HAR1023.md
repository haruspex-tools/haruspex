# HAR1023: two of the source's folders hold the same scripts

**Error.** Found before the SQL files are read. It stops the run: nothing is written.

## What it means

`source` lists several folders, and two of them hold the same scripts: the same folder listed twice (`db` and `./db/`, or
`Tables/` and `tables/` on a file system that ignores case), one folder inside another (`db` and `db/tables`), or two folders
that reach one folder through a link.

## Why haruspex reports it

The folders are read as one database, and every script is read once. Read twice, a script that creates a table or a procedure
would define it twice ([HAR1002](HAR1002.md)), which says less about the mistake than naming the two entries; and one that
creates a trigger or alters a table would be read twice without any error at all
([decision 0127](../decisions/0127-a-source-may-be-several-folders.md)).

## What to do

List each folder once. Where one folder is inside another, list the outer folder alone, or list the folders inside it that are
the database's and leave the outer one out. Where a link joins them, list one of the two, or remove the link.

## Example

```text
haruspex: error HAR1023: db/inner is inside db, so its scripts would be read twice. List db alone, or list its folders but not it.
```
