# HAR3023: set names that can't be used

**Error.** Found reading the config file, or applying it to a query file. It stops the run: nothing is written.

## What it means

A procedure's `sets`, or a query file's `-- @sets` comment, isn't a list of names it can use: it is empty or not an array, or a name isn't in camel case (a
lower-case ASCII letter, then letters and digits), is a word the generated code's language reserves, is given twice, or is
`output` or `returnValue`.

## Why haruspex reports it

Each name is a key of the object the procedure's function returns, beside `output` and `returnValue`, so it must be one the
generated code can write and no two sets can share one
([decision 0070](../decisions/0070-a-procedure-s-result-sets-are-named-all-or-none.md)).

## What to do

Give each set a name of its own in camel case, such as `["order", "lines"]`.

## Example

```text
haruspex.json:1:129: error HAR3023: procedures["lib.get_book"].sets[1]: 'output' can't name a set: the function already returns its OUTPUT parameters under it.
```
