# HAR3025: a schema in two modules

**Error.** Found reading the config file. It stops the run: nothing is written.

## What it means

`split` lists a schema in two modules. Schema names are compared ignoring case, as SQL Server compares them, so `sales` and
`Sales` are one schema.

## Why haruspex reports it

A schema's procedures are in one module, so each of their schemas, types and functions is written once, and every name stays
unique across the config's files
([decision 0074](../decisions/0074-a-config-may-split-its-output-into-modules.md)).

## What to do

List the schema in the one module that should hold its procedures, and remove it from the other.

## Example

```text
haruspex.json:1:116: error HAR3025: split.stock[0]: the schema LIB is in the module loans already, at line 1; a schema's procedures are in one module. Schema names are compared ignoring case, as SQL Server compares them.
```
