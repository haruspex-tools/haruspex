# HAR6012: the IR in the output folder is of another version

**Error.** Found by `haruspex check`, comparing with the files in the output folder. The check fails, with exit code 1, and nothing is
written.

## What it means

The `haruspex.ir.json` in the output folder is of an IR version this haruspex doesn't read: it was written by an older or newer
haruspex. The message names both versions.

## Why haruspex reports it

A reader refuses a file of another version ([decision 0024](../decisions/0024-an-ir-reader-reads-only-versions-whose-documents-mean-what-its-own-do.md)),
because what a claim means may have changed between versions, so no claim can be compared. Comparing the modules alone would
let such a change pass unseen.

## What to do

Run `haruspex generate` with the version you mean to use, read the change to the module (`git diff`), and commit both
files. A new version of haruspex is a change to review, like a change to the database.

## Example

```text
out/haruspex.ir.json: error HAR6012: this file is IR 0.9, and this haruspex writes IR 0.25, so the two can't be compared claim by claim. Run haruspex generate with this version, read the change to out/haruspex.zod.ts before committing it, and commit both.
```

**See also:** [The command line](../../src/Haruspex.Cli/README.md), and [decision 0050](../decisions/0050-check-compares-claims-not-files.md) for why `check` works so.
