# HAR1002: an object is defined more than once

**Error.** Found reading the SQL files. It stops the run: nothing is written.

## What it means

Two scripts create the same object (a table, a view, a procedure, a function, a type or a synonym), compared as SQL
Server compares names, ignoring case.

## Why haruspex reports it

Which definition applies would depend on the order the scripts are run in, which a folder of scripts doesn't fix. Rather
than guess, haruspex stops.

## What to do

Keep one definition. If one script changes an object another creates, write the change as an `ALTER` or a `DROP` and
`CREATE`: haruspex reads those, and says where the order matters.

## Example

```text
db/p2.sql:1:1: error HAR1002: lib.get_book is defined more than once.
```
