# HAR1002: an object is defined more than once

**Error.** Found reading the SQL files. It stops the run: nothing is written.

## What it means

Two scripts create the same object (a table, a view, a procedure, a function, a type or a synonym), compared as SQL
Server compares names, ignoring case. Within one script, a second `CREATE` with no drop before it is reported too, and so is a
synonym created again after a drop that may not run (under an `IF` whose condition isn't known), which is reported at the drop.
So is a `CREATE SYNONYM` for another target that may run, under an `IF`, in a block or a body, or in a deployment script,
which is reported where it is.

## Why haruspex reports it

Which definition applies would depend on the order the scripts are run in, which a folder of scripts doesn't fix, or on
whether a drop runs. Rather than guess, haruspex stops.

## What to do

Keep one definition. If one script changes an object another creates, write the change as an `ALTER` or a `DROP` and
`CREATE`: haruspex reads those, and says where the order matters.

## Example

```text
db/p2.sql:1:1: error HAR1002: lib.get_book is defined more than once.
```
