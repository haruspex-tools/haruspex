# HAR6011: nothing in the output folder to check against

**Error.** Found by `haruspex check`, comparing with the files in the output folder. The check fails, with exit code 1, and nothing is
written.

## What it means

`haruspex check` found no IR, no module, or neither, in the output folder (`out` in the config file,
or `--out`), or no `haruspex.files.json`, the list of the files `generate` wrote, which it goes by to remove the files it no
longer writes ([the files generate removes](../configuration.md#the-files-generate-removes)). The message names each file that
isn't there. A folder an earlier version of haruspex wrote has no list: run `haruspex generate` once, and commit the list.

## Why haruspex reports it

`check` compares what haruspex would write with the files in the output folder, which in CI are the ones committed. With
none there, there is nothing to compare, and
passing would let a module that was never generated, or an `out` that names the wrong folder, through CI without a word.

## What to do

If the module is new, run `haruspex generate`, read what it writes, and commit every file. If they are committed, check that
`out` names the folder they are in.

## Example

```text
haruspex: error HAR6011: nothing to compare with: out/haruspex.ir.json, out/haruspex.zod.ts and out/haruspex.files.json aren't there. Run haruspex generate, read what it writes, and commit it.
```
